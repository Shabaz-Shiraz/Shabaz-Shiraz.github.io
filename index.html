// about

Phones live in messy conditions. My apps are built for that.

Patchy networks, aggressive battery savers, calls in the middle of a task, one-handed use on a bus. That is where Android apps actually run, so that is what I design for.

At Codelynks I own features end to end: reading the requirement, building it, testing it, shipping it and supporting it in production. Seeing my own code in Crashlytics is the best teacher I have had, and it is why I care about release builds, R8 rules and healthy CI pipelines.

My default setup is Jetpack Compose with MVI: one immutable state per screen, intents in, no hidden state in views. I am now bringing the same approach to Kotlin Multiplatform.

Architecture

MVI and Clean Architecture with Hilt, so screens stay predictable and easy to test.

Modern UI

Compose-first features, and step-by-step migrations off legacy Fragments.

Integrations

Payments, sign-in, push, BLE devices and real-time streams done securely.

Reliability

Crashlytics, Analytics, R8 and Jenkins to keep releases stable and boring.
